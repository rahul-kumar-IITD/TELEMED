# E5-S1: Frontend shell with auth screens, session and route guards

- Epic: E5 (Frontend Experience)
- Layer: UI
- Group: D
- Estimate: L
- Depends on: E1-S4
- Brief criteria covered: NFR-04

## Description

Build the React app shell: API client, register and login screens, sessionStorage token handling, role-specific home redirects, route guards, not-allowed and not-found pages, and shared loading, empty and error states. Ported from the HTML mockups in specs/design/mockups/ (the visual contract).

## Acceptance Criteria

1. A successful login stores the access token in sessionStorage and never in localStorage.
2. After login a patient lands on the doctor search route, a doctor on the daily queue route and an admin on the user list route.
3. An unauthenticated visit to a protected route redirects to /login, a wrong-role visit shows the not-allowed page, and an unknown or another user's object shows the not-found page.
4. A 401 from any API call clears the session and redirects to /login, and a 503 shows a generic try-again message.
5. Register and login screens show a duplicate-email message on 409 and one generic message on login failure, and have no horizontal scroll at 375px and 1280px.
6. Error messages are rendered in an ARIA live region, and every screen exposes loading, empty and error states.
