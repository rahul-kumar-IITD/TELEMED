# E3-S5: Doctor can drive the appointment lifecycle and see a daily queue

- Epic: E3 (Appointment Booking and Lifecycle)
- Layer: API
- Group: H
- Estimate: L
- Depends on: E3-S3
- Brief criteria covered: AC-08, NFR-02

## Description

The appointment state machine is enforced server side. Each valid transition appends exactly one event. Doctors view a daily queue in the provider timezone, and each appointment response lists the allowed next actions so the UI never re-implements the rules.

## Acceptance Criteria

1. The doctor can move an appointment BOOKED to CHECKED_IN to IN_PROGRESS to COMPLETED, each call returns 200, and exactly one event with actor role DOCTOR is appended per transition.
2. Invalid transitions (BOOKED to IN_PROGRESS, BOOKED to COMPLETED, CHECKED_IN to CANCELLED, and any change from COMPLETED, CANCELLED or NO_SHOW) return 409 InvalidAppointmentStateException and append no event.
3. NO_SHOW is refused with 409 before the start time and accepted with 200 from BOOKED or CHECKED_IN after the start time, and the slot stays BOOKED.
4. GET /api/doctors/me/queue?date=YYYY-MM-DD returns only the caller's appointments whose start falls on that date in PROVIDER_TIMEZONE, ordered by start time.
5. Each appointment response includes allowed_actions that match the state machine, and NO_SHOW appears only once the start time has passed.
6. Only the appointment's doctor can transition it: another doctor receives 404 and a patient receives 403.
