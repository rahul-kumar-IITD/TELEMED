# E1-S4: Server-side authentication and role separation on every route

- Epic: E1 (Platform and Identity)
- Layer: API
- Group: C
- Estimate: M
- Depends on: E1-S3
- Brief criteria covered: NFR-04

## Description

Provide the auth dependency that validates the JWT, loads the user and role from the database on each request, rejects deactivated users, and enforces role and ownership rules with the BRD status codes (401, 403, 404). Admins can access every route.

## Acceptance Criteria

1. A request to a protected route with no token, a malformed token or an expired token returns 401.
2. The role is read from the database, so a valid token claiming role ADMIN for a user whose stored role is PATIENT receives 403 on an admin route.
3. A user with the wrong role for a route receives 403, and a user of the right role requesting another user's object receives 404.
4. A user deactivated after logging in has the still-valid token rejected with 401 on the next request.
5. An ADMIN user receives 200 on patient routes, doctor routes and admin routes when the object exists.
