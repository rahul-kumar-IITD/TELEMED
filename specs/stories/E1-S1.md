# E1-S1: Domain types, schema and append-only protections exist

- Epic: E1 (Platform and Identity)
- Layer: Repository
- Group: A
- Estimate: L
- Depends on: none
- Brief criteria covered: NFR-01, NFR-02, NFR-05

## Description

Define the enums, value types and SQLAlchemy models for every entity in the BRD data model, with Alembic migrations. Money is stored as integer minor units and exposed as Decimal. SQLite triggers make profile versions, appointment events and consultation notes append-only.

## Acceptance Criteria

1. Running `alembic upgrade head` on an empty SQLite file creates tables users, patient_profiles, patient_profile_versions, doctor_profiles, availability_templates, slots, appointments, appointment_events and consultation_notes.
2. UPDATE and DELETE statements against patient_profile_versions, appointment_events and consultation_notes are each rejected by a SQLite trigger and leave the row unchanged.
3. A fee of Decimal('500.00') is persisted as the integer 50000, read back as Decimal('500.00'), and no float type appears in fee or money code paths.
4. Every new SQLite connection reports journal_mode 'wal' and a busy_timeout of at least 5000 ms.
5. Inserting a slot with a status outside AVAILABLE/BOOKED/BLOCKED, or an appointment with a status outside BOOKED/CHECKED_IN/IN_PROGRESS/COMPLETED/CANCELLED/NO_SHOW, is rejected by a CHECK constraint.
6. Migrations are append-only (NFR-05): a test fails if any already-committed Alembic revision file is modified or deleted, new schema changes are added only as new revisions, and no migration drops or rewrites rows of the append-only tables.
