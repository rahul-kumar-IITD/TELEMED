# E4-S2: Admin can list, deactivate and reactivate users and edit patient profiles

- Epic: E4 (Records and Administration)
- Layer: API
- Group: G
- Estimate: M
- Depends on: E1-S5, E3-S2
- Brief criteria covered: AC-01, NFR-04

## Description

Admins view all users, deactivate and reactivate them under the BRD safety rules, and edit patient profiles on a patient's behalf (appending a new profile version).

## Acceptance Criteria

1. GET /api/admin/users returns all users with role and active flag, and ?role=DOCTOR filters to doctors only.
2. Deactivating a patient returns 200, after which that patient's login returns 401, their existing token returns 401, and their existing appointments remain and can still be processed by the doctor.
3. Deactivating a doctor with a BOOKED, CHECKED_IN or IN_PROGRESS appointment returns 409, while a doctor with only terminal appointments deactivates with 200 and disappears from search.
4. An admin deactivating their own account receives 409 and remains active.
5. Reactivating a user returns 200, the user can log in again, and a reactivated doctor reappears in search.
6. PUT /api/admin/patients/{id}/profile inserts a new profile version for that patient and leaves earlier versions unchanged.
