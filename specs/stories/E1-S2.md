# E1-S2: Platform skeleton with health, logging and error mapping

- Epic: E1 (Platform and Identity)
- Layer: Config
- Group: A
- Estimate: M
- Depends on: none
- Brief criteria covered: NFR-03, NFR-06, NFR-07

## Description

Create the FastAPI app, typed settings, structured JSON logging with correlation IDs, the /health endpoint and the exception-to-status mapping used by every later API story. No PHI may ever reach logs.

## Acceptance Criteria

1. GET /health returns 200 with body {"status":"ok"} within 1 second of the process starting.
2. Every response carries an X-Request-ID header: a valid incoming value is echoed back, and a missing or invalid value is replaced by a generated UUID.
3. Each log line is valid JSON containing correlation_id, and a request whose body contains an email, name or note text produces log lines that contain none of those values.
4. SlotUnavailableException and InvalidAppointmentStateException map to 409, naive datetimes and malformed input map to 422, and a SQLite lock timeout maps to 503 with a generic body.
5. Settings load PROVIDER_TIMEZONE (default UTC), JWT lifetime, database path and busy timeout from environment, and an unknown timezone name aborts startup with an error naming PROVIDER_TIMEZONE.
