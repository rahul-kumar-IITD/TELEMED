# E3-S2: Patient can book an appointment atomically

- Epic: E3 (Appointment Booking and Lifecycle)
- Layer: API
- Group: F
- Estimate: L
- Depends on: E2-S3, E2-S4, E3-S1
- Brief criteria covered: AC-04, AC-05, NFR-08

## Description

A patient books an AVAILABLE slot. The slot claim is a single conditional UPDATE inside one transaction that also inserts the appointment and its BOOKED event. Concurrent attempts on one slot produce exactly one success and the rest receive SlotUnavailableException (409).

## Acceptance Criteria

1. POST /api/appointments with an AVAILABLE slot_id returns 201 with an appointment_id and status BOOKED, the slot becomes BOOKED, and exactly one BOOKED event is appended.
2. 20 concurrent POST /api/appointments requests for the same slot return exactly one 201 and nineteen 409 responses, and none return 503.
3. Booking a BOOKED, BLOCKED, past or more-than-14-days-ahead slot returns 409 and creates no appointment.
4. Booking a slot belonging to a deactivated doctor returns 409 even when the slot id is supplied directly.
5. Only PATIENT users may book: a doctor receives 403 and an unauthenticated caller receives 401.
6. A successful booking calls the payment stub exactly once and the response includes the fee as a string such as "500.00".
