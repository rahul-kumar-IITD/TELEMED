# E2-S2: Admin can onboard a doctor with an availability template

- Epic: E2 (Providers and Availability)
- Layer: API
- Group: D
- Estimate: M
- Depends on: E1-S4, E2-S1
- Brief criteria covered: AC-10, NFR-01

## Description

Admins create doctor accounts with specialty, languages, fee and a weekly availability template. Onboarding validates the template, creates the user, profile and template in one transaction, and triggers slot generation. Doctors are never self-registered.

## Acceptance Criteria

1. POST /api/admin/doctors with valid details returns 201 with a doctor_id, creates a user with role DOCTOR, stores the fee as "500.00", and generates slots for the next 14 days.
2. A non-admin caller receives 403 and an unauthenticated caller receives 401 on POST /api/admin/doctors.
3. A template whose end is not after start, whose slot length is zero or negative, or whose slot length does not divide the window returns 422 and persists nothing.
4. A fee that is non-numeric, negative or has more than 2 decimal places returns 422.
5. Onboarding with an email that already exists returns 409 and creates nothing.
6. The newly onboarded doctor can log in with the admin-supplied initial password and receives a token whose database role is DOCTOR.
