# E1-S5: Patient can view and update a versioned profile

- Epic: E1 (Platform and Identity)
- Layer: API
- Group: D
- Estimate: M
- Depends on: E1-S4
- Brief criteria covered: AC-01, NFR-02, NFR-03

## Description

Patients maintain their profile (identity details). Every update inserts a new row in patient_profile_versions and the current profile is the latest version, preserving full history.

## Acceptance Criteria

1. GET /api/patients/me/profile returns 200 with the latest profile version for the logged-in patient.
2. PUT /api/patients/me/profile inserts a new version row and leaves all earlier version rows byte-identical.
3. After two successive updates, GET /api/patients/me/profile returns the values from the second update.
4. A doctor calling /api/patients/me/profile receives 403 and a patient requesting another patient's profile by id receives 404.
5. A profile update writes a log line containing user_id but none of the submitted profile values.
6. A profile update may change full_name, age, gender and phone (partial PUT; omitted fields carry forward; age stays an integer in 1..130), and is accepted only from the owning patient or an admin; a doctor or another patient is refused with 403 and no version row is added (AC-01).
