# E3-S4: Patient can reschedule an appointment atomically

- Epic: E3 (Appointment Booking and Lifecycle)
- Layer: API
- Group: H
- Estimate: L
- Depends on: E3-S3
- Brief criteria covered: AC-07, NFR-02

## Description

A patient moves a BOOKED appointment to another open slot of the same doctor. The target claim, the old slot release and the RESCHEDULED event happen in one transaction, the appointment id is unchanged, and the 60-minute rule applies.

## Acceptance Criteria

1. POST /api/appointments/{id}/reschedule {new_slot_id} returns 200 with the same appointment_id, the new slot becomes BOOKED and the old slot becomes AVAILABLE.
2. A RESCHEDULED event is appended containing both the old slot id and the new slot id.
3. A target slot that is booked, blocked, already started, outside the 14-day window, the same slot, or another doctor's returns 409 and changes nothing.
4. Rescheduling less than 60 minutes before the current start returns 409, while exactly 60:00 before start returns 200.
5. Rescheduling an appointment in CHECKED_IN, IN_PROGRESS, COMPLETED, CANCELLED or NO_SHOW returns 409.
6. If a failure is injected after the target slot is claimed, the transaction rolls back and both slots and the appointment keep their original state.
